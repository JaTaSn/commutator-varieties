## What Theorem 12 (`thm-mingens`) needs

The article proves it from exactly two lemmas and nothing else — no codimension, no determinantal
structure, no external citation:

1. **generic** — a homogeneous ideal generated by finitely many same-degree forms that are linearly
   independent over the base field has that set as a *minimal* generating set;
2. **independence** — the three components of `w_k` are linearly independent over `F`, for `k ≥ 2`.

`KCommuting/MinimalGenerators.lean` states (1). It is deliberately first: it is stateable without
any of the commutator construction, so it separates *"how hard is mathlib here"* from *"how hard is
this particular ideal"* — which is the whole point of a calibration trial.

## One deliberate narrowing

The article states (1) for an arbitrary graded ring; the Lean version is for `MvPolynomial σ F`.
That costs nothing — the article only ever applies it to `R_k = ℚ[v_1,…,v_k]` — and buys a great
deal, because mathlib's `IsHomogeneous` / `homogeneousComponent` API is much better developed than
its general `GradedAlgebra` one.

### The composite is a checked declaration, not a claim in a report

`KCommuting/Theorem12.lean` exists solely to *compose* the two halves —
`isHomogeneous_w'` and `w_linearIndependent` into `three_generators_minimal` — and so to put
Theorem 12 for the real `w k` into the repository as something Lean has checked. Two halves living
in separate files, with "and therefore the theorem follows" left to prose, is exactly the situation
in which the last step goes unverified indefinitely. It is a separate module so that
`Independence` need not import `MinimalGenerators`; the two are otherwise independent.

### Three regression tests guard against silent weakening

Cheap, and each pins something a future edit could quietly break:

- two `rfl` checks under `def w`, pinning the base case at 2 (the bug that made every `w k` wrong);
- an `example` after `vars_w_lt` pinning the load-bearing freshness instance, block `k` fresh for
  `w k` — the instance the *pre*-correction statement could not produce;
- two `example`s after `w_linearIndependent` showing independence genuinely **fails** at `k = 0, 1`,
  where `w` is junk. Without these, `2 ≤ k` is indistinguishable from a hypothesis carried out of
  habit, and the theorem indistinguishable from one that holds for all `k` for uninteresting
  reasons.

Independently checked, 2026-08-31, rather than taken from the session that produced it: rebuilt from
clean, re-ran `lean_verify` on the headline declarations, confirmed the diff to `Independence.lean`
contains **zero deletions** (so nothing previously proved was weakened to make room), and confirmed
`w 2` is genuinely nonzero — evaluating to 1 at an explicit point — so the freshness and
independence statements constrain a polynomial that actually has variables.

Freshness was the piece the cost table below called *"medium — the main cost"*, and that estimate
was fair: it needed the containment form `vars (w n i) ⊆ {blocks < n}`, which inducts where the
membership form does not, plus four helper lemmas to carry it through the constructors the recursion
uses. Two mathlib imports had to be added — `Algebra.MvPolynomial.CommRing` for `vars_neg` and
`vars_sub_subset`, which are genuinely *not* reachable through `Algebra.MvPolynomial.Variables`
despite the name, and `Algebra.MvPolynomial.PDeriv`.

**The statement had to be corrected before it could be proved.** The `sorry`'d version was written
against the pre-fix `w` and excluded only blocks `≥ n+1`, missing block `n` itself — which is the
one the argument needs, since `w (k+1) = D (w k) ⨯₃ v k` crosses with block `k`. It was true but
unusable. The corrected form, and a regression `example` pinning the load-bearing instance, are in
the file.

So homogeneity — item 2 of "two corrections" below, the ingredient nobody had listed — is now
discharged, and it came in at the "small" the cost table predicted: about 35 lines including the
three helper lemmas, with no wrong turns beyond re-hitting the `AddMonoidAlgebra` dot-notation trap
already recorded in the file.

**A defect found while doing it, worth more than the lemma.** The `w` recursion did not define the
article's `w_k`. Written `| 0 => … | 1 => … | (n+2) => D (w (n+1)) ⨯₃ v (n+1)`, its `w 2` took the
*recursive* branch, giving `D (w 1) ⨯₃ v 1` where the file's own docstring said `v 0 ⨯₃ v 1` — so
every `w k` was off by one twisted cross product. Established by `rfl`-check, not by reading. Fixed
by pinning the base case at 2; two `example … := rfl` regression tests now sit under the definition
so the same slip cannot recur silently. Nothing proved earlier depended on it, since none of the
proved declarations mention `w`.

So the article's *generic* lemma (`lem-mingens-generic`, "independent same-degree generators are
minimal") is fully formalized, for `MvPolynomial σ F`.

**The base case was cheaper than costed, and for a reason worth keeping.** The cost table below
rates `k = 2` — independence of the three `2 × 2` minors of a generic `2 × 3` matrix — as *medium,
fiddly rather than deep*, on the assumption that it would be done by evaluating `coeff` at three
hand-picked private monomials (`X₍₁,₀₎X₍₂,₁₎`, `X₍₂,₀₎X₍₀,₁₎`, `X₍₀,₀₎X₍₁,₁₎`). None of that was
needed. `w 2 = v 0 ⨯₃ v 1` is *itself* a cross product with a fresh variable block, so it is an
instance of the same engine the inductive step uses: block `1` is fresh for `v 0`, so steps 1–3 run
unchanged and return a nonzero constant `d` with `d ⬝ᵥ v 0 = 0`, which the degenerate case of
`cross_eq_zero_of_dot_v_eq_zero` (constants have empty `vars`) contradicts at once. The base case is
five lines.

The generalization that made this work is `exists_dot_eq_zero_of_cross_v`: steps 1–3 packaged for an
arbitrary coefficient vector `a` free of block `m`, rather than written out twice. It is invoked with
`a = v 0, m = 1` at the base and `a = D (w k), m = k` at each step. **Estimate versus actual:** the
table below priced the whole of `lem-mingens-indep` at 250–400 lines and one focused day; the
assembly on top of the already-proved parts came to about 60 lines of tactic script, with the base
case being the part that collapsed.

## Closing `mem_span_of_mem_ideal_span` — second session, 2026-08-30

Twelve lines, about fifteen minutes, one wrong turn. The shape is exactly the one the plan
predicted: pull a finite representation out of the ideal membership, apply `homogeneousComponent d`
to both sides, and let the already-proved graded step collapse every polynomial coefficient to its
constant term.

```
obtain ⟨t, hts, c, hc⟩ := (Submodule.mem_span_image_iff_exists_fun _).mp hmem
x = homogeneousComponent d x            -- homogeneousComponent_eq_self
  = homogeneousComponent d (∑ i : t, c i • g i)
  = ∑ i : t, homogeneousComponent d (c i • g i)      -- map_sum
  = ∑ i : t, coeff 0 (c i) • g i        -- the graded step, then smul_eq_C_mul
then Submodule.sum_mem / smul_mem / subset_span
```

**Which mathlib lemma to use.** Of the three candidates considered,
`Submodule.mem_span_image_iff_exists_fun` is the right one:

```
x ∈ span R (v '' s) ↔ ∃ t : Finset α, ↑t ⊆ s ∧ ∃ c : t → R, ∑ i, c i • v i = x
```

It is stated for `v '' s` — an *image*, which is exactly how the generating set is written here —
and it hands back a `Finset` of the index type together with the proof that it sits inside `S`, so
the final `subset_span` step is one `Set.mem_image_of_mem`. `Finsupp.mem_span_image_iff_linearCombination`
also exists and is the underlying lemma, but returns a `Finsupp` and a `linearCombination`, which
would have to be unfolded to a sum by hand. `Ideal.mem_span_image_iff_exists_fun` does **not**
exist (checked); `Ideal.span` is defeq to `Submodule.span` over the ring itself and the `Submodule`
lemma applies to it directly with no rewriting.

**Wrong turn (a fifth for the collection).** `Submodule.mem_span_image_iff_exists_fun.mp hmem`
fails with `Unknown constant Submodule.mem_span_image_iff_exists_fun.mp` — a misleading message,
because the constant *does* exist. The cause: the ring `R` is an **explicit leading argument** of
that lemma (it is stated under `variable (R : Type*)`), so the bare name elaborates to a `∀`-type,
not to an `Iff`, and Lean cannot use generalized field notation on it; it then falls back to
reading the whole dotted string as a constant name and reports that failure instead of the real
one. Writing `(Submodule.mem_span_image_iff_exists_fun _).mp hmem` fixes it. **Heuristic: an
"Unknown constant `Foo.bar.mp`" where `Foo.bar` is known to exist means `Foo.bar` has explicit
arguments before the `Iff`, not that the name is wrong.**

## What Theorem 12 (`thm-mingens`) still needs — a costed estimate, not an attempt

Task (2) of the second session was the article's `lem-mingens-indep`. It was **not** attempted:
scoping it made clear it is a day's work, not an hour's, and the instruction was to cost it rather

### First, two corrections to how the job was described going in

1. ~~**The twist is not `diag(-1,-1,1)`.**~~ **Superseded 2026-08-31 — and now the reverse is
   true.** As written on 2026-08-30 this item said the twist *was* `τ(a,b,c) := (b,a,2c)`, that
   anything built on `diag(-1,-1,1)` "would formalize a different object", and that the standing
   hypothesis char `FF` ≠ 2 existed exactly to make `τ` invertible. The merge of the two source
   manuscripts settled the question the other way: the article now uses
   **`D = diag(-1,-1,1)`** throughout, and `KCommuting/Independence.lean` was written against `D`
   from the start, so the two agree and the warning above is inverted.

   The consequence for the formalization is a real simplification, not just a renaming. `D` is an
   involution with `det D = 1`, so it is invertible in **every** characteristic; `τ`, with
   `det τ = -2` and `τ² = diag(1,1,4)`, was not. The independence argument leans on the twist's
   invertibility, so under `τ` that step consumed char `FF` ≠ 2 and under `D` it consumes nothing —
   no `[NeZero (2 : F)]`, no `ringChar F ≠ 2`, no side conditions to thread. The article's standing
   char ≠ 2 is now spent solely on inverting `enc` in Step 1 (see `prob-char2`), which the
   formalization never touches, since it works with `w_k` directly rather than with matrices.
2. **Homogeneity is a third missing ingredient, not counted in the original two.**
   `three_generators_minimal` needs `hhom : ∀ j, (g j).IsHomogeneous d` as well as `hind`. For the
   real `w_k` that is `(w_k)ⱼ` homogeneous of degree `k`, which is its own induction
   (`w₂ = v₁ × v₂` is degree 2; each step adds one via `IsHomogeneous.mul`/`.sub`). Cheap, but
   nobody had listed it.

### The mathematical argument, worked out (the article's proof sketch is not quite complete)

*(Rewritten 2026-08-31 for `D`; the argument is unchanged in shape, and one hypothesis lighter.)*

Write `u := D(w_{k-1})` (and `u := v₁` at `k = 2`), so `w_k = u ⨯₃ v_k` with `v_k` a block of
three *fresh* variables not occurring in `u`. A relation `∑ aᵢ (w_k)ᵢ = 0` with `aᵢ ∈ F`, read off
coefficient-wise in the three fresh variables, is exactly `a ⨯₃ u = 0`.

The article's original sketch said this "would force the twisted `w_{k-1}` itself to be a constant
vector". That is not what it forces, and the gap matters for formalization: it forces the three
components of `u` to be pairwise `F`-proportional, i.e. to span an `F`-subspace of dimension ≤ 1.
The induction therefore has to carry *linear independence of `w_{k-1}`'s components* (which gives
dimension 3 ≥ 2), not non-vanishing. `lem-nondeg`'s non-degeneracy, which the sketch cited here, is
a strictly weaker statement and does not close this step on its own — the article now records that
explicitly, in `rem-nondeg-insufficient`. The induction does go through with the stronger
hypothesis, and invertibility of the twist is what transports independence from `w_{k-1}` to `u`.
Under `D` that invertibility is free in every characteristic, so unlike the `τ` version this step
carries no hypothesis at all.

## The calibration signal — which is what this trial was for

The article's proof is one sentence: *a polynomial-coefficient combination reproducing one generator
from the others, while staying in the same degree, can only use degree-0 coefficients.*

Formally that is two very unequal steps:

1. **the graded step** — for `φ` homogeneous of degree `d` and arbitrary `c`, the degree-`d`
   component of `c * φ` is `C (constant term of c) * φ`;
2. **the linear-algebra step** — conclude from `LinearIndependent`.

Step 2 is a single mathlib lemma, `LinearIndependent.notMem_span`. **Step 1 is not in mathlib.**
Searched by type pattern and by exact name: mathlib has `homogeneousComponent_eq_self`,
`homogeneousComponent_isHomogeneous`, `homogeneousComponent_of_mem`, `IsHomogeneous.mul`, and — the
near miss — `homogeneousComponent_C_mul`, which is exactly this statement for a coefficient that is
*already constant*. The general case must be built.

**That is the finding.** It is not hard mathematics — but it had to be built.

**Now proved, and the estimate was too pessimistic.** I guessed 30–80 lines; the finished proof is
**20 lines of tactic script**, verified by `lean_verify` to depend on nothing but `propext`,
`Classical.choice` and `Quot.sound` — no `sorryAx`. It went coefficient-wise rather than by
decomposing `c` into homogeneous components, which is what the sketch above proposed and would
indeed have been longer:

```
ext m; rw [coeff_homogeneousComponent, coeff_C_mul]
by_cases on whether deg m = d
  · coeff_mul turns the product into a sum over the antidiagonal, and
    Finset.sum_eq_single (0, m) kills every term: if deg x.2 = d then
    deg x.1 = 0, so x.1 = 0 and x.2 = m; otherwise φ's coefficient vanishes.
  · both sides are 0, by IsHomogeneous.coeff_eq_zero.
```

**Four wrong turns, all cheap, all worth recording** — they are what a formalization session
actually costs:

1. `coeff_mul` needs `DecidableEq σ`; `classical` supplies it.
2. The antidiagonal lemma is `Finset.mem_antidiagonal`, not `Finsupp.mem_antidiagonal`.
3. **There is no `Finsupp.degree_add`** — and there needn't be: `degree` is a bundled
   `AddMonoidHom`, so additivity is plain `map_add`. Ten minutes lost looking for a lemma that
   should not exist.
4. Destructuring the antidiagonal element with `rintro ⟨p, q⟩` left `(0, q).2` unreduced in a
   hypothesis, which then defeated `zero_add`. Working with `x.1`/`x.2` instead avoided it.

**Revised signal.** One representative degree-bookkeeping step, the kind this article leans on
constantly, cost about 20 lines and four small false starts — an hour's work, not a day's. That is
considerably more encouraging than the first estimate, and it is a measurement rather than a guess.
The plan's refusal to commit to the full formalization on one data point still stands, but the data
point is now favourable.

Nothing here argues against formalizing; it prices it. The plan's instruction not to commit to the
full formalization on the strength of one trial still stands.
